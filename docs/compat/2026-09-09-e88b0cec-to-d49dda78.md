## Rationale (2026-09-09 re-pin `e88b0cec…` → `d49dda78…`)

The break is permitted pre-1.0 with the `compat:breaking` label. The removed ABI lines are of two kinds:

- **Source-visible type changes (few, migration-documented).** `usage.serverToolUse` on the Anthropic messages
  result and streaming delta events changed from `AnthropicServerToolUsage` to the OpenRouter-specific
  `OrAnthropicServerToolUsage` (an audited nested `allOf`-resolution overlay elects the refined upstream branch);
  and `McpCallItem.error` / `McpCallItemView.error` changed from `String?` to the structured `McpToolCallError?`.
  The `1 generated file removed` (Kotlin-source layer) is the retired inline
  `InlineMessagesDeltaEventUsageServerToolUse…` type, subsumed by `OrAnthropicServerToolUsage`.
- **Mechanical generated all-args constructor moves (the bulk of the −122 / −120 lines).** Additive upstream
  fields appended arguments to many generated models' primary constructors, so each changed constructor is a `−`
  line — but these are not real API removals: the builder DSLs (`xxx { … }`) and deserialization stay additive, and
  only code that calls a changed all-args constructor **positionally** must supply the new argument.

Migration guidance for the source-visible changes is in
[`../migration/0.x-generated-renames.md`](../migration/0.x-generated-renames.md); the CHANGELOG `Breaking` section
summarises both kinds. The four new operations (OAuth JWKS/token, SCIM sync jobs) and the 24 added schemas are
purely additive.
