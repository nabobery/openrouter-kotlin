# Migrate from 0.x to 1.0

OpenRouter Kotlin 1.0 establishes compatibility guarantees for the curated API and the generated operation signatures
of the pinned OpenRouter contract. This guide consolidates every consumer-visible incompatibility introduced before the
1.0 freeze.

If you already compile against `0.1.0-rc.1`, review the type and constructor changes below. Earlier development builds
also need the symbol and client-default migrations.

## Update the dependency

Use the root multiplatform coordinates; Gradle selects the appropriate platform variant:

```kotlin
dependencies {
    implementation("io.github.nabobery:openrouter-kotlin:1.0.0")
    testImplementation("io.github.nabobery:openrouter-kotlin-testing:1.0.0")
}
```

Do not depend directly on suffixed target artifacts such as `openrouter-kotlin-jvm`.

## Update renamed symbols

| Before | 1.0 replacement | Action |
| --- | --- | --- |
| Earlier generated root name | `OpenRouterClient` | Prefer the curated `OpenRouter` facade; use `OpenRouterClient` only for exact generated access. |
| `OpenRouterBuilder.trustHost(...)` | `OpenRouterBuilder.trustOrigin(origin)` | Pass a complete trusted origin: scheme, host, and optional port. |
| `client.betaResponses` / `BetaResponsesClient` | `client.responses` / `ResponsesClient` | Import and call the GA Responses client. |
| `client.betaAnalytics` / `BetaAnalyticsClient` | `client.analytics` / `AnalyticsClient` | Use the GA Analytics client. |

## Adapt changed generated types

The 2026-09-08 pinned contract refined two generated fields:

- `usage.serverToolUse` on Anthropic Messages results and streaming deltas is now
  `OrAnthropicServerToolUsage`. Existing web-search and web-fetch counters remain available, and the type adds
  `toolCallsExecuted` and `toolCallsRequested`.
- `McpCallItem.error` and `McpCallItemView.error` are now `McpToolCallError?`, not `String?`. Read the structured
  error fields instead of treating the value as a message string.

```kotlin
val webSearches: Int? = result.usage.serverToolUse?.webSearchRequests
val executedToolCalls: Int? = result.usage.serverToolUse?.toolCallsExecuted
```

Additive upstream fields also changed several generated all-arguments constructors. Code using the builder DSLs or
deserialization is unaffected. For direct positional construction, supply the new arguments or migrate to the builder
DSL so future additive fields do not require call-site churn.

## Remove calls that only reapplied client defaults

Retry policies, deadlines, observers, the shared retry budget, and the SDK User-Agent now reach every generated call
through the client configuration. `OpenRouter.options { ... }` represents per-call overrides only.

```kotlin
// Before: required only to make client defaults take effect.
client.chat.sendChatCompletionRequest(request, options = client.options())

// 1.0: client defaults apply automatically.
client.chat.sendChatCompletionRequest(request)

// Keep options only when this call differs from the client configuration.
client.chat.sendChatCompletionRequest(
    request,
    options = client.options { retry(RetryPolicy.Resilient) },
)
```

## Review the experimental API boundary

The stable 1.x compatibility promise excludes declarations marked `@OpenRouterExperimentalApi`. In 1.0 this marker
covers one transfers-and-pagination cluster: byte-stream helpers, transfer observers, file upload/download helpers,
STT upload, `PaginationLimits`, and `FilesClient.listAllFiles`.

These APIs remain available behind `@OptIn(OpenRouterExperimentalApi::class)`, but may change incompatibly in a future
minor release with release notes. Removing the marker from a declaration is an additive graduation.

## Verify the migration

After updating imports and affected field access, run your normal multiplatform compilation and tests. For projects
using the companion test kit, keep `openrouter-kotlin` and `openrouter-kotlin-testing` on exactly the same version.

The complete 1.0 stability boundary is defined in [ADR 0008](../adr/0008-1-0-api-freeze-and-stability-guarantees.md).
